- **D1 DEMONSTRATED (HIGH, blocks durability claim) — `statePath` accepted but ignored; default `:memory:` defeats restart durability.** `cli/hosted.ts:23,69` parses `--state-path` into the command; `createHostedSupervisor` (`cli/hosted.ts:141-190`, line 176) builds `deps.hostedStore ?? new HostedStore(":memory:")` and never reads `options.statePath`. So a supervised run that passes `--state-path` silently runs on an in-memory journal: every pid/start/fence row the P0 fix depends on vanishes on restart, and `recover()` can hold nothing. The author's RED false-stop test passes only because provider + store share one process. Required executable evidence (author tasked): on-disk test — claim/start with `statePath` file, kill the supervisor process, re-`createHostedSupervisor` from the same path in a new process, assert the mapping + pid record survive and `recover()` holds; plus a test that omitting `statePath` either persists to a documented default file or fails loudly (never silent `:memory:` in the production handler path).
- **D2 DEMONSTRATED by source read (HIGH) — persisted `runtime_started_at_mono_ms` is compared against a NEW process's `performance.now()` after restart.** `hosted-store.ts:269+` persists `startedAtMonoMs` from the spawning process's monotonic clock; `stopAndConfirm` (`hosted-supervisor.ts:453-463,515-519`) computes `performance.now() − mapping.runtime_started_at_mono_ms` in whatever process performs the stop. `performance.now()` origin is per-process (time since process start), so after a restart the subtrahend belongs to a dead clock: elapsed is garbage (typically huge → clamped by the `min(bound)` in `markStopped`, masking the error as full-budget consumption, or negative → clamped to 0). Demonstrated by code semantics (no committed test exercises cross-process elapsed); a same-process test cannot catch it. Required evidence: executable test asserting either (a) wall-clock (`Date.now()`) start persisted alongside/instead-of mono for cross-restart elapsed, with mono used only in-process, or (b) restart path always takes `markHeldUnknown` (reserved budget, unknown flag) and never reports measured elapsed from a stale mono origin.

Speculative until executed: killing an *unrelated recycled* pid (requires pid reuse + live victim at that number; not reproduced). Grade accordingly: the missing identity check is a demonstrated code fact with a demonstrated over-permissive consequence (ghost resolves); cross-process victim-kill is a real but unexecuted hazard.
