## What the candidate gets right (verified, not assumed)

1. **Real Coordinator+Store reuse, not a parallel orchestrator.** `hosted-supervisor.ts:206-260` creates the local worker via real `store.create` (idempotent `request_id: hosted-<task>`), pauses via real `coordinator.control(id,"pause")`, creates the VM handle via the provider, then starts the controlled child; `stopAndConfirm` (`340-397`) calls real `coordinator.control(id,"cancel")` best-effort and only afterwards requires provider-verified stop. No shadow dispatch, no second tick loop, no Store-table mutation (HostedStore uses its own `hosted_mappings`/`hosted_idempotency` tables).
2. **Durable mapping before cloud ACK before start.** `claimOnce` (`70-123`) writes `claimMapping` (task/lease/fence row, `pending-<task>` placeholder) immediately after the claim transport; `ackAndStart` (`126-275`) resolves/creates the row, performs the ack HTTP call, and only after a valid ack + authority check stages/starts. Ack-denied (401/409) → `markStopIntended`; network failure → `markHeld`, never blind re-exec (`162-170`).
3. **Restart/ambiguity holds.** `recover()` (`440-458`) marks every non-settled row `held`, returns them, never calls spawn/re-exec; tests `crash before/after mapping` and `held capacity` assert `held` + zero `spawnedCommands` + fence-8 replay rejected + settle refused without confirmed stop.
4. **Duplicate/lost-ack/fence/idempotency.** `claimMapping` reuses same (task,lease,fence), throws on fence/lease mismatch (`85-144`); `updateLease` enforces same-fence/same-lease (`195-217`); idempotency table binds tenant+principal+resource+operation+fingerprint with conflict-on-mismatch (`295-353`); rotation uses one durable pending key per window, consumed on successor, invalidated on 401/409 (`hosted-client.ts:392-465`); settlement requires `stop_confirmed` on both sides (`supervisor.settle` + `markSettled` guard).
5. **Confirmed stop done right.** `stopAndConfirm` never reads the Coordinator `cancelled`/`paused` label as proof — it requires `provider.stopWorkerRuntime()` resolution (SIGTERM→SIGKILL→kill(pid,0)-fails = dead) or provable absence; uncertainty → `markHeld` + throw ("holding reservation"). This directly satisfies the lead's follow-up finding. Real subprocess tests prove start (exit 0 in ~900 ms), verified stop, and parent-death EOF (exit 3).
6. **Clock/RTT authority is monotonic-server-based.** `remainingAuthorityMs` = min(lease,deadline) − server_time − full RTT − margin; tests prove ahead-clock and eaten-lease refuse start. Claims/acks parse strict Zod incl. `server_time`, `lease_expires_at` nullable-guard, `controlled_duration_ms ≤ runtime_ms ≤ 1 h`, tenant-equality at transport and supervisor layers.
7. **No secrets in env/payloads/logs.** Child env is `{PATH,TZ}` only (never `process.env`); `exec`/`readFile`/`writeFile` refuse arbitrary use; route payloads carry only UUIDs/durations; CLI rejects `sf*` argv secrets; the poisoned-env test asserts no bearer/provider/model secret in output or spawned commands; credential files use the approved 0600/0700/no-follow/fsync helper via static import.
8. **Watchdogs exist on both ends of the child.** Supervisor `setTimeout(duration)` → `stopAndConfirm("watchdog deadline")`; child self-exits at its own absolute timer plus stdin-EOF parent-death handling. The lease-expiry server-side sweeper is explicitly out of scope (no D1 bridge yet) — see gap G2.

## Findings (severity-ordered, each with repro/evidence)

- **B1 BLOCKING — compiled-binary portability: `runtimeScript` path does not exist in the shipped binary.** `hosted-runtime.ts:22-27` resolves `new URL("../scripts/hosted-controlled-runtime.ts", import.meta.url).pathname`. Compiled-probe evidence (built with the repo's own target on pinned Bun 1.4.2): `import.meta.url` inside a `--compile` binary is `file:///$bunfs/root/probe`, so the derived pathname is `/$bunfs/scripts/hosted-controlled-runtime.ts` — not a real file. The shipped `swarmforge` binary (built and `--help`-verified here) contains **zero** occurrences of `hosted-controlled-runtime` (strings count 0), and the `hosted` CLI is unwired, so no test exercises the compiled hosted path. Consequence: any future `swarmforge hosted supervisor` run from the standalone binary (the release artifact; "no external bun/repo files assumed") will spawn a nonexistent script and fail closed (or worse, resolve unpredictably) — the entire controlled execution path is currently source-checkout-only. Fix before integration: embed the child as a build artifact (e.g. compile the runtime script into the binary / run with `bun run` from bundled source / subcommand dispatch inside the same binary via `Bun.spawn([process.execPath, ...])` with an internal entrypoint), plus a test that launches the hosted flow from the compiled binary in an empty directory. Related: spawning uses `process.execPath` (the supervisor binary itself in compiled flow) with a `.ts` script argument — unverified under `--compile` even if the path existed.
- **B2 MUST-FIX (pilot gate, explicit gap) — no real D1/workerd bridge: server authority unproven.** All 4 "SIMULATED transport" tests use `Bun.serve` fixtures the author controls; the file header honestly states the lead adds the real bridge later. I do **not** certify claim/ack/renew/settle server semantics (fencing increments, stop directives, settlement binding, `server_time` honesty) from HTTP mocks. Required later: workerd+D1 integration proving duplicate-claim single-winner, fencing rejection, stop-before-release, and idempotent settlement against the real backend.
- **B3 MUST-FIX — pause-hold assumes `control(pause)` works on a fresh worker; failure path is swallow-and-continue.** `ackAndStart:228-232` wraps `coordinator.control(local,"pause")` in try/catch with comment "Already paused or terminal: keep holding". But a freshly `store.create`d worker is `queued`, and `runControl` rejects pause unless state is `paused` (queued → intent=pause → `teardown` never called; actually for non-paused non-vm state it falls to `provider.pauseWorker` — needs verification against the exact base). If the pause genuinely fails open (exception swallowed), the Coordinator tick could provision/dispatch the staged worker (its prompt is the inert probe, and ControlledAgent.submit is a no-op, so blast radius is bounded — but the "Coordinator can never dispatch model work" comment then rests on agent no-op rather than the pause). Fix: assert the post-pause state is actually `paused` (read back `store.get`) or otherwise gate start on an explicit hold the tick respects; add a regression test that runs a real Coordinator tick between staging and start and asserts no dispatch.
- **M1 SHOULD-FIX — watchdog/renew timers die with the process; only the child side survives a supervisor crash.** `recover()` correctly holds mappings, but in-memory `renewTimers`/`watchdogs` are gone after restart — server-side lease expiry then depends on the (not yet built) D1 sweeper. Acceptable for the inert pilot if the D1 sweeper + `recover()`-driven `stopAndConfirm` reconciliation lands together; record it as a joint acceptance criterion, not as proven today.
- **M2 SHOULD-FIX — `HostedStore` is a second SQLite file/connection, not the Store's transaction.** Mapping-before-ack is durable, but claim-row vs canonical-worker-row vs ack are separate transactions across two DBs; crash windows are handled by hold-and-reconcile (good), but there is no cross-DB atomicity — document the windows explicitly in the protocol doc rather than implying atomicity.
- **N1 NOTE — known prerequisite vs new defect.** The `cloud-worker-client` "old 09 tmp fallback" referenced in the dispatch is not present in this candidate: `hosted-client.ts:392-465` + `private-credential-file.ts` implement the durable-pending-key rotation the dispatch says was "already fixed 32b230f and approved elsewhere"; the 09db215 cherry-pick commit message is internally consistent (static helper import, round-trip tests). `32b230f`/`09db215` do not resolve in my checkout's object store (unfetched worker branches), so I verified behavior from the candidate's own tests (9/9 pass) rather than from the upstream review — distinguish accordingly. No frozen-lockfile drift (diff empty; install used `--frozen-lockfile`).
