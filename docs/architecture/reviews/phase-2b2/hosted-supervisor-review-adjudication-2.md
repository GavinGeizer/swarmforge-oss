- **P0 CONFIRMED — false confirmed-stop after restart (empty in-memory `children` map proves nothing).** Source: `hosted-runtime.ts:36-47` `getWorker` returns `null` when `children` has no entry; `hosted-runtime.ts:107-115` `stopWorkerRuntime` resolves when `!child && getWorker(id) === null`. Independent repro (pinned Bun 1.4.2, real inert child, single targeted script — not the full suite): provider A starts the fixed 5 s child; after 300 ms A reports `running`; fresh provider B (models a post-restart supervisor with an empty map) `stopWorkerRuntime` **resolves** while A's child is still `running`. Output: `B.stopWorkerRuntime: RESOLVED (claims confirmed stop)` + `A.getWorker after B.stop: …"state":"running"`. So `stopAndConfirm` → `markStopped(stop_confirmed=true)` → settlement can proceed while the OS process still executes. Root cause: the liveness map is process-local memory; after restart nothing binds `controlled-<worker>` to a real OS pid, and `vm_id` carries no pid. Required fix + real regressions: (a) durable pid binding (persist child pid alongside the mapping at start; `getWorker`/`stopWorkerRuntime` must resolve the pid from durable state, `kill(pid,0)`-verify liveness, SIGTERM→SIGKILL→reap, and only then claim absence); (b) regression: start child, drop the provider (fresh instance, same durable state), assert `stopWorkerRuntime` on the stale/empty handle either kills the real pid or throws uncertain — never resolves while the process lives; (c) regression: actual kill confirmed via waitpid/exit + `kill(pid,0)`-fails.
- **P1 CONFIRMED (by source read) — `consumed_runtime_ms` measures stop latency, not execution.** `hosted-supervisor.ts:340-397`: `const started = Date.now()` is taken at the top of `stopAndConfirm`, and `markStopped(taskId, Date.now()-started, …)` records that delta as `consumed_runtime_ms`, which `settle` then sends as terminal reservation evidence. That delta is coordinator-cancel + provider-stop latency, not bounded execution time. Required fix: derive consumption from execution bookkeeping (`startedAt`/`authorityMs`/child exit timing), not the stop path stopwatch; regression asserting settlement evidence is bounded by actual runtime.
- **P2 CONFIRMED (by source read) — ack RTT is computed before the HTTP ack completes.** `hosted-supervisor.ts:154` computes `rtt = Date.now() - requestStartedAt` before `await client.ack(...)` (`157-161`); the value passed as `requestRttMs` therefore excludes the ack round trip itself and under-subtracts, over-granting authority. Required fix: measure RTT across the awaited ack (or bound it conservatively); regression with a delayed ack fixture asserting authority shrinks accordingly.
