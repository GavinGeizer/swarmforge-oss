## Report limitations and corrections

- [architecture-original.md](architecture-original.md) incorrectly names Hono. The application uses vanilla Workers handlers and Zod. [architecture-checkpoint.md](architecture-checkpoint.md) mislocates activity tracking and shows an invented schema: actual throttled updates are in `machines.ts`, `last_seen_at` already exists in the Phase 2B.1 migration, and no extra column migration was required at `69fd0ab`.
- [deployment-readiness-original.md](deployment-readiness-original.md) contains inaccurate counts, storage and quota descriptions. Actual schema has **15 tables** after two migrations; private local CLI file storage is plaintext with restrictive permissions; encrypted retry caches are separate D1 data. Application budgets are implemented. An unrelated master diff or framework stub is not implementation evidence.
- [abuse-cleanup-original.md](abuse-cleanup-original.md) overstates a 90-day default or KV dependency. Cleanup preserves audits by default and uses D1, not KV. Audit retention is an unresolved owner policy; optional bounded pruning must be explicitly selected.
- [credential-final.md](credential-final.md) checks real client tests and traces server code, but root HTTP fixtures do **not** independently validate server crypto/tenant enforcement. Rate limiting is already implemented; distributed quota exhaustion and edge CPU remain unresolved rollout limits.
- [final-auth-original.md](final-auth-original.md) ran some cloud fixtures with an incorrect runner and misclassified resulting mock-provider errors as network restrictions. [final-auth-b93-followup.md](final-auth-b93-followup.md) reports all 52 passing under Node. Some per-file counts and descriptions in that report are inaccurate: the real CLI file has one integration test, and the dashboard fix corrects revision consistency rather than a demonstrated credential leak. See the actual tests and consolidated validation record.
- [final-architecture-original.md](final-architecture-original.md) approved `d284bf3` while calling its one root failure flaky. The lead required the deterministic fix and another exact-commit review. Reports do not establish untested live OAuth, remote preview or edge CPU results.
- [final-architecture-approved.md](final-architecture-approved.md) miscounts the added hostile test file as 13; it has **10**, included in the actual 52 total. Its release approval applies to the feature implementation, not permission for production deployment.
- [final-security-original.md](final-security-original.md) independently executes the correct cloud runner and traces successor authentication/batch guards, but overstates encoded-token detection and audit behavior. Generic machine prefixes cover raw unknown tokens; encoded variants apply to loaded known secrets. A failed atomic batch rolls back both mutation and its success audit; `INSERT OR IGNORE` cannot audit through D1 failure. The report's grouped test counts, some line references and universal idempotency claims are inaccurate. Link/invitation retry caches are bounded by their original expiry. Its broad deployment language is not accepted as evidence of live preview or quota readiness.
- [final-security-corrected.md](final-security-corrected.md) withdraws those overstatements and explicitly preserves rollout caveats. Some named test/file mappings and line references still differ from source. Four listed cases reside in `additional-hostile.integration.ts`; helpers define fixtures, not tests. The direct audit-outage/rollback evidence is `enrollment.integration.ts`'s **audit or database failures cannot partly enroll, consume or authorize machine identities**, which drops the audit table and asserts no partial grant, and `auth.integration.ts`'s audit rollback tests. Rotation concurrency alone is not audit-failure evidence. Preview wrappers are in `scripts/migrate-preview.mjs` / `deploy-preview.mjs`; no `scripts/preview.ts` exists. The actual suite and source, rather than mislocated prose citations, support the accepted conclusions.
- Several workers began with snapshot Bun 1.3.14, although the project requires 1.4.2. Frozen-lockfile/tool failures on that runtime are not product regressions. Cloud integration must run with the package's Node 24 test script; direct Bun execution does not intercept workerd outbound mocks correctly.
