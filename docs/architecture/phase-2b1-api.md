# Phase 2B.1 implemented identity APIs

This attachment supersedes the **linking/enrollment portions only** of the proposed Phase 1 contracts. Phase 2A account APIs and owner/admin/member roles remain. UUID identifiers, Unix millisecond timestamps, strict JSON validation, 128 KiB bodies, no-store responses, generated request IDs and `{error:{code,message,request_id}}` errors are unchanged. Host/path/query are checked; duplicate parameters are rejected. Signed keyset cursors bind current user, organization or installation and purpose, expire after ten minutes, and confer no authority. All list limits are 1–100, default 20.

Website identity is a cookie session; mutations require exact trusted Origin and `X-CSRF-Token` from `/v1/session`. Authorization headers cannot be combined with cookie authority. CLI, worker, enrollment and initiating proofs have distinct formats, database bindings and consumers. No GitHub/instance token is accepted. Database, audit or rate-limit failure denies closed with coarse 503.

## CLI linking

| Method/route | Authentication and authorization | Request and response |
| --- | --- | --- |
| POST `/v1/cli-links` | Public allocation, `Authorization: LinkInitiator <43-char base64url initiating secret>` and `Idempotency-Key`. No tenant authority. | `{client_name,requested_scopes:["identity:read","devices:self"],tenant_id?:UUID}`. 201 `{link_id,user_code,verification_url,expires_at,poll_interval_seconds:5}`. `client_name` printable 1–100 chars. `user_code` random 12-char base64url; verification_url has link ID only, never initiating proof. |
| GET `/cloud/connect?link_id=UUID` | Active website session; otherwise fixed GitHub web sign-in with allowlisted return target. | HTML with installation name/scopes, own organization choices, pairing-code input, explicit approve/deny. Data renders through textContent, script nonce/CSP, no credentials embedded. |
| GET `/v1/cli-links/{id}` | Website session only. ID identifies pending approval, never grants tenant authority. | `{link_id,client_name,scopes,requested_tenant_id,expires_at,state}`. No initiating proof, pairing code, approving account or issued credential. |
| GET `/v1/cli-links/{id}/status` | Initiating proof matching transaction. | `{state,expires_at,poll_interval_seconds:5}`. No account/org details. Poll budget atomically advances; premature requests get 429. |
| POST `/v1/cli-links/{id}/approve` | Website session/CSRF, pairing code, current active membership in selected org; rechecked in write transaction. | `{user_code,tenant_id}` plus Idempotency-Key. `{link_id,state:"approved",tenant_id}`. If initiation requested a tenant, approval must select exactly it. Approving account/org/session are immutable after approval. |
| POST `/v1/cli-links/{id}/deny` | Website session/CSRF and pairing code. | `{user_code}` plus Idempotency-Key. `{link_id,state:"denied",tenant_id:null}`. |
| DELETE `/v1/cli-links/{id}` | Original initiating proof. | `{state:"cancelled"}` for pending/approved/cancelled; cannot cancel a consumed grant. Revoke the installation instead. |
| POST `/v1/cli-links/{id}/exchange` | Original initiating proof and Idempotency-Key, body `{}`. | Pending: 202 `{state:"pending",poll_interval_seconds:5}`. Approved: 200 Credential below. Consumption, installation/credential creation and audit are atomic. Approval session, account and membership must remain active at initial exchange. |

States: pending/approved/denied/cancelled/consumed. Ten-minute expiry. Five invalid code attempts lock approval; only an authenticated browser with CSRF may attempt approval. Initiating secret has 256 bits and is hashed at rest. Code is hashed and separately encrypted for start retries. No proof/code is accepted as customer identity. Start retry requires identical proof/key/normalized body. Approval retry requires same account/session/org/key/code. Conflicts are 409. Exchange replay returns the same credential only with the original proof and same key before link expiry, with the issued credential still active. Cache is AES-GCM encrypted. Another key cannot create/retrieve a second grant. Lost response after cache expiry requires a fresh browser pairing.

CLI Credential = `{credential:"sfcli_"+43-char random token,credential_id,installation_id,subject_id,tenant_id,scopes:["identity:read","devices:self"],expires_at,authorization_expires_at}`. Token hash only in credential table; encrypted short-lived retry cache is separate. Credential lifetime 24 hours, bounded by a 30-day browser authorization window. Re-pair to extend the window. These are technical defaults, not commercial subscription entitlements.

## CLI installations

| Method/route | Policy | Contract |
| --- | --- | --- |
| GET `/v1/cli/me` | CLI bearer, exact audience/scopes and current active account/org/membership. | `{installation_id,subject_id,tenant_id,client_name,scopes,expires_at,authorization_expires_at}`. No token returned. |
| GET `/v1/cli/organizations?limit=&cursor=` | Same CLI principal; queries only its authorizing user's active memberships. | `{items:[{tenant_id,display_name,role}],next_cursor}`. Listing is for fresh browser reauthorization; cannot change the installation's tenant. Cursor also bound to installation. |
| DELETE `/v1/cli/me` | Current CLI bearer; self only. | `{installation_id,revoked_at}`. Invalidate installation epoch and every credential with audit in one batch. Subsequent use is 401, including repeated self logout. |
| POST `/v1/cli/me/rotate` | Current CLI bearer; `{}`, Idempotency-Key. | New CLI Credential, same immutable org/user/installation, next epoch; prior token denied immediately on general routes. Exact proof/key retry is permitted only on this route for at most ten minutes and original token expiry, while successor/current authority remains active. |
| GET `/v1/tenants/{tenant}/cli-installations?limit=&cursor=` | Website session/current membership. Owner/admin list all tenant devices; member lists own only. | `{items:[{installation_id,tenant_id,subject_id,client_name,status,created_at,authorization_expires_at,revoked_at}],next_cursor}`. Tenant/user-qualified queries and cursors. |
| DELETE `/v1/tenants/{tenant}/cli-installations/{id}` | Website session/CSRF. Owner/admin manage tenant devices; member own only. | `{installation_id,revoked_at}`. Resource-idempotent; original revoked timestamp preserved. Cross-tenant/other-member IDs 404. |

No route trusts requested organization IDs for CLI authorization. `cloud use` initiates a new browser link constrained to the target organization; changing a local file does not change issued authority. No bearer access to website settings/session APIs. The narrow initial CLI scope does **not** authorize worker administration; those operations require an owner/admin website session in this phase.

## Customer worker identity

| Method/route | Policy | Contract |
| --- | --- | --- |
| POST `/v1/tenants/{tenant}/worker-enrollments` | Owner/admin website session/CSRF, Idempotency-Key. Active authority rechecked atomically. | `{name}` -> 201 `{enrollment_id,enrollment_secret:"sfenroll_"+43-char random token,expires_at}`. Ten-minute, org-bound invitation. Maximum 25 active invitations per tenant. Matching authorized session/key/body may replay encrypted result until consume/revoke/expiry. |
| DELETE `/v1/tenants/{tenant}/worker-enrollments/{id}` | Owner/admin website session/CSRF, tenant ownership. | `{enrollment_id,revoked_at}`, stable repeats. Stops invitation use/replay; existing worker identity is removed via worker revoke. |
| POST `/v1/workers/register` | `Authorization: Enrollment <enrollment_secret>`, Idempotency-Key. No website/CLI/GitHub credential substitute. | `{enrollment_id,name,runtime_version,capabilities}`. Name printable 1–100; version 1–64; at most 20 hints of 1–64 chars. Hints confer no authority; invitation's name/org are authoritative. 201 `{...WorkerCredential,worker}`. Recheck issuing account/admin membership/org and invitation session before first consume. |
| GET `/v1/workers/me` | Worker bearer, current epoch/expiry, active organization and authorizing owner/admin account/membership. | `{worker_id,tenant_id,audience:"worker-identity",scopes:["worker:identity","worker:rotate"],registration_epoch,expires_at,authorization_expires_at}`. |
| POST `/v1/workers/me/rotate` | Same worker principal, `{}`, Idempotency-Key. | New WorkerCredential, next epoch; same bounded exact-context retry semantics as CLI rotation. |
| GET `/v1/tenants/{tenant}/workers?limit=&cursor=` | Owner/admin website session, tenant membership. | `{items:[Worker],next_cursor}`, tenant-scoped cursor. |
| DELETE `/v1/tenants/{tenant}/workers/{id}` | Owner/admin website session/CSRF and tenant ownership. | `{worker_id,revoked_at}`; stable repeats invalidate epoch/credentials. No physical stop promised: there is no dispatch/runtime in this phase. |

Worker = `{worker_id,tenant_id,name,state:"registered"|"revoked",registration_epoch,created_at,revoked_at}`. WorkerCredential = `{credential:"sfworker_"+43-char random token,credential_id,worker_id,subject_id,tenant_id,scopes:["worker:identity","worker:rotate"],expires_at,authorization_expires_at}`; subject_id records the authorizer and confers no account authority. Worker credential lifetime one hour; authorization at most 30 days, then fresh invitation/enrollment. Registration is one logical identity with encrypted same-secret/key/body retry until invitation expiry and while credential remains valid. A changed body/key returns 409. Maximum 100 registered workers and 100 active CLI installations per organization are enforced at atomic admission.

This is identity enrollment only. Phase 1's heartbeat/dispatch scopes and remote_worker_enrollment paid capability do not apply to execution here: no heartbeat, task, usage, VM, inference, repository broker or entitlement API is implemented. Registration does not claim eligible compute or authorize a workload. Future execution must add server capabilities/reservations/leases before dispatch; it cannot infer them from enrolled identity.

## Errors, resource limits and revocation

Besides Phase 2A safe 400/401/403/404/405/413/503: 409 idempotency_conflict/link_conflict/link_consumed/enrollment_consumed/rotation_conflict/enrollment_limit; 410 link_expired/enrollment_expired; 403 link_denied/approval_locked/authorization_changed; 429 slow_down/rate_limited with Retry-After. Wrong proof/resource is 404; wrong credential kind/audience/expiry/revocation is 401. Unsupported/malformed fields cannot change tenant/scopes/epochs. Private list queries verify current authority on each page.

No auth cache. Membership removal, account disablement, organization suspension or worker authorizer's admin downgrade immediately deny **subsequent authentication checks**. In-flight operations may complete at their transactional boundary; privileged writes recheck authority inside their D1 batch. Existing unrevoked grants become usable again if an operator restores the same account/membership/org and the bounded grant remains valid. Permanently revoke installations/workers when removal must invalidate existing credentials permanently. Ownership transfer does not automatically transfer worker/device authorizers: old authorizer must remain eligible, otherwise re-enroll. Website logout does not revoke already consumed machine grants; pending approved exchange/enrollment still depends on its issuing session. Expired grant requires fresh authorization; clock comes from server.

Rate budgets are D1-backed fixed one-minute windows keyed by HMAC of edge CF-Connecting-IP/group; absent IP uses a shared bucket, never X-Forwarded-For. OAuth starts 20/min, callbacks 60/min, links starts 10/min, linking routes 90/min, worker routes 60/min, other private routes 120/min. Public callback denial audits max eight/min/IP; authenticated denial audits max eight/min/user. Other unauthenticated failures do not allocate audit rows. Successful security mutations remain transactional/audited. Rejected exhausted buckets do not increment counters. Readiness/health are coarse, public, and exempt. Per-link pending/status polls also have a five-second atomic budget. Network-distributed abuse still requires edge protection; these limits do not prove Free quota fit.
