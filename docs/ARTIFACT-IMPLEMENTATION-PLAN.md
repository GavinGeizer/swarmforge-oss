# Artifact retrieval and worker salvage plan

Baseline: `5672ead2a526e07fea9ed11e58b3725e42013527`.

## Findings and decisions

The coordinator persists control intents and dispatch/results in SQLite, polls OpenCode over HTTP, and calls `WorkerProvider` for VM management and filesystem operations. Freestyle 0.2.13 already supplies `fs.readFileStream` with byte ranges and cancellation. Existing `WorkerFiles` and MCP artifacts expose only live VM files under `.swarmforge/artifacts`; their component stat/read sequence has a symlink race. There is no worker daemon. Completion/failure retain VMs; destruction is explicit and already checks source durability. Preserve these protections.

Extend the provider filesystem abstraction. A small trusted guest helper securely opens workspace paths with descriptor-relative `O_NOFOLLOW`, copies bounded regular files into private staging while computing SHA-256, or creates a bounded regular-file-only tar.gz snapshot. Helper execution returns metadata only. File bytes travel through the existing Freestyle binary filesystem transport into a storage backend. No model participation, file contents in exec output, or base64 reconstruction.

Raw bytes remain faithful and private. Model-facing reads stay bounded and credential screened, including encoded secret variants and chunk boundaries. An authenticated HTTP download is an explicit raw-byte operation; it shares existing host/origin/token checks. No archive extraction is introduced.

Use a durable finalization record separate from the task outcome, so completed/failed/cancelled remain meaningful to current clients. The preservation stage is visible independently as pending/collecting/preserved/failed/abandoned. Normal destruction requires preservation to settle successfully or explicitly abandon it through force destruction; exhausted automatic retries retain the VM and expose a retry operation. Existing Git safety checks remain in force. No new automatic VM deletion policy.

## Shared contracts (owners must coordinate changes through the lead)

- `WorkerProvider` gains optional `artifactTransport?: WorkerArtifactTransport` imported from `src/artifact-types.ts`. Production Freestyle implements it; unsupported providers fail clearly rather than using unsafe stat/read fallback.
- `WorkerArtifactTransport` exposes `list(vmId, root, path, {offset?,limit?,signal?,maxEntries?,maxDepth?})`, `open(vmId, root, path, {maxBytes,signal?})`, `snapshot(vmId, root, {paths?,maxBytes,maxEntries,maxDepth,signal?})`, and `diagnostics(vmId, root, {maxBytes,signal?})`. `open`/`snapshot` return `ArtifactTransfer {stream: ReadableStream<Uint8Array>,size:number,sha256:string,filename:string,cleanup():Promise<void>}`. Diagnostics returns `{path:string,transfer:ArtifactTransfer}[]`. Listing returns `{entries:{name:string,kind:string,size?:number}[],next_offset:number|null}`. Use workspace-relative paths, at most 32 components and 1024 bytes; reject traversal, absolute paths, backslashes, NUL/control characters, symlinks and special files. Snapshot supports safe files/directories, excludes `.git` and `node_modules` by default, enforces source/output byte, entry and depth bounds, and never extracts archives.
- `ArtifactService` in `src/artifacts.ts`: constructor `(config: Config, store: Store, provider: WorkerProvider)`; `preserve(workerId,path,options?:{signal?:AbortSignal,runId?:string|null,kind?:string}) -> Promise<ArtifactRecord>`; `snapshot(workerId,options?:{signal?:AbortSignal,paths?:string[],runId?:string|null}) -> Promise<ArtifactRecord>`; `diagnostics(workerId,options?:{signal?:AbortSignal,runId?:string|null}) -> Promise<ArtifactRecord[]>`; `list({worker_id?,task_id?,offset?,limit?}) -> {artifacts:ArtifactRecord[],next_offset:number|null}`; `metadata(artifactId) -> ArtifactRecord`; `read(artifactId,offset?,length?) -> Promise<Uint8Array>` (private raw bounded range); `download(artifactId,signal?) -> Promise<ReadableStream<Uint8Array>>`; `listWorkerFiles(workerId,path?,options?)`; `collectDirectory(workerId,path,options?:{signal?,runId?}) -> Promise<ArtifactRecord[]>`; `safeRead(artifactId,offset?,length?) -> Promise<Uint8Array>` credential screened, at most 32768 returned bytes. Public safe metadata wrappers pass through the coordinator's redactor.
- `ArtifactRecord`: artifact_id, task_id, worker_id, run_id nullable, original_path, storage_key nullable, filename, size, sha256 nullable, created_at, retrieved_at nullable, state (`preserving`/`preserved`/`failed`), attempts, error nullable, kind. Metadata is persisted in an artifact repository initialized from `store.db`; writes are atomic, partials never visible as preserved, repeated same worker/run/path/content is idempotent. Store interface permits a future object backend.
- `Coordinator.artifacts: ArtifactService`; `Coordinator.retryFinalization(workerId)`; `Worker.finalization?` contains state (`pending`/`collecting`/`preserved`/`failed`/`abandoned`), run_id nullable, attempts, error nullable, next_retry_at nullable, started_at nullable, completed_at nullable. Durable historical events retain attempts and outcomes.
- Spawn accepts optional `artifacts: {path:string,required?:boolean}[]` (max 100), and optional `snapshot_on_failure:boolean` default false. Paths are relative to configured workspace. Direct files and directories are supported; trailing `/**` means that directory, other wildcards rejected. Missing optional paths are skipped; transport failures remain errors. Default collections: `.swarmforge/artifacts`, `.swarmforge/logs`, result/metadata files and diagnostics. Full workspace snapshots are explicit or configured on failure.
- Config defaults: `SWARMFORGE_ARTIFACT_DIR` defaults beside DB to `artifacts` (memory DB uses temporary private storage); `SWARMFORGE_ARTIFACT_MAX_BYTES=1073741824`; `SWARMFORGE_ARTIFACT_MAX_ENTRIES=10000`; `SWARMFORGE_ARTIFACT_MAX_DEPTH=32`; `SWARMFORGE_ARTIFACT_TIMEOUT_MS=120000`; `SWARMFORGE_FINALIZATION_MAX_ATTEMPTS=3`; `SWARMFORGE_FINALIZATION_RETRY_MS=2000`; `SWARMFORGE_ARTIFACT_CONCURRENCY=4`. Enforce safe integer bounds. Bound concurrent transfers/finalizations, including direct API calls.

## Implementation packages

1. **Data plane and storage**: owns `src/artifact-types.ts`, `src/artifact-store.ts`, `src/artifacts.ts`, `src/providers/artifact-transport.ts`, `src/providers/freestyle.ts`, `src/files.ts`, and new transport/store/artifact tests plus local transport fixture. Implement secure staging and streaming, SHA-256 comparison, cancellation, private local storage, durable metadata, idempotent recovery, bounded safe reads, directory collection and tar.gz snapshots. Extend existing live WorkerFiles to use secure capture while preserving bounded resource semantics. Fix Freestyle fetch signal combination.
2. **Lifecycle and persistence**: owns `src/coordinator.ts`, `src/domain.ts`, `src/store.ts`, `src/config.ts`, `src/finalization.ts`, `src/security.ts`, `tests/helpers.ts`, lifecycle/restart/token-idle/git/safety tests and new finalization tests. Persist finalization before collection; run it after completion, abnormal failure, cancellation and before normal destruction. Retry with persisted count/backoff, restart collecting rows safely, hold dispatches until collection settles, and let cancel/force destroy abort transfers before acquiring worker lock. Persist explicit abandonment before provider deletion. Missing VMs explicitly record preservation failure/abandonment. Avoid control-intent wedges and retain source safety.
3. **Manager APIs, observability and docs**: owns `src/mcp.ts`, `src/http.ts`, `src/metrics.ts`, `src/providers/opencode.ts`, `docs/ARTIFACTS.md`, existing architecture/protocol/API/observability docs and README, `tests/api.test.ts`, `tests/http.test.ts`, new MCP/download/metrics tests, and `scripts/artifact-salvage-smoke.ts`. Add list/get metadata/preserve/read/snapshot/retry primitives; bounded safe inline reads; authenticated raw streaming download with byte ranges if straightforward. Metrics use persisted records/events without per-worker labels or contents. Document failure retention, retry/force, roots/limits, faithful private raw storage versus safe excerpts, snapshots and end-to-end recovery. Realistic smoke exercises actual filesystem helper + binary stream + SQLite + deletion with OpenCode unavailable, and can target a real Freestyle VM explicitly.

Each worker writes failing behavioral tests first and records red/green evidence, commits only owned files on its assigned branch, and reports the exact head, tests, limitations and dependencies. Shared interfaces are decided here, not duplicated in scratch production code. Missing sibling modules may be used only as temporary test scaffolding outside the tracked checkout until their real commits can be fetched.
